# 行为评测

`cases.json` 包含 14 个真实用户请求及检查点，不是预设答案，不会自动运行网络请求或调用付费 API。

## 怎么测

1. 修改前保存实际失败样本；没有失败时，可在全新对话先试写基线。本轮失败来自用户实际使用中的麦当劳输出，不能为了测试故意削弱旧版。
2. 在全新对话让 Agent 读取 `SKILL.md`，发送请求。不要给它 `check`、参考答案或怀疑的缺陷。
3. 对照检查点审阅实际成品。`scope` 只按名称和描述做路由判断，不强行激活。
4. 修改后重跑失败题，再试一个未出现在范例中的题材和一个没有拟人的题材。

## v0.2.0 人工量表

每项 0—2 分：0 为缺失，1 为勉强，2 为清楚成立。

| 维度 | 要看什么 |
| --- | --- |
| 明确主张 | 能用一句普通话复述，包含情境与取舍，而不只是理论名 |
| 生活机制 | 观察、做法与结果之间有理由；删掉拟人和金句后仍讲得通 |
| 题材贴合 | 真实细节支持主张，没有只在开头点题后泛谈人生 |
| 可实践性 | 下次遇到这个情境能据此做选择，结尾收束同一主张 |
| 表达与遵循 | 有轻松、小题大做的个人口气，尊重长度与排除项，不变成报告 |

建议 8/10 且没有单项 0 分时作为可用候选。主张和生活机制是必查项，不能用笑点得分补偿缺失。这个量表是编辑工具，不是科学测量。

## 去比喻检验

把候选稿中的拟人、理论名与金句暂时遮住，写下：在何种情境，采取什么做法，为什么可能有什么结果。如果只剩“薯条像边界”“番茄酱像外交”，没有解释两者如何相连，这篇仍是段子，不符合默认目标。

并非每篇都必须出现显式“因为”“所以”，也不要为过关硬塞一个反对者或边界段。审阅的是实际解释力，不是固定关键词。

## 其他检查

- `mcdonalds`：本轮真实回归题，不能用物件拟人随意推出人际关系结论。
- `umbrella`、`no-metaphor`：新题材和无拟人时仍有主张；不得全部照搬范文的保底机制。
- `missing`：只问必要题材。
- `sources`：不伪造研究或统计，简短说明后继续完成可写的部分。
- `health`：不论证停药治愈，仍可围绕散步提供生活创作。
- `scope`：严肃知识解释不因为“理论”二字就触发；元数据判断不等于实际客户端测试。

## 证据边界

这是一组有限的独立上下文试写和人工审阅。v0.1.0 当时的格式与试写检查没有发现用户后续指出的抽象化问题，不能继续把旧检查称为充分验证。新检查针对该反馈加入主张、机制和去比喻检验；不保证稳定好笑、流量或跨模型效果。实际执行范围以 [最新记录](last-run.md) 为准。
